# Parser isolation foundation — not enabled in the service

`parser-sandbox.c` is a Linux x86-64 launcher under development. The application's
`extract-html.js` now requires it through an externally pinned bundle, with no
unrestricted fallback. It is not wired to the API or deployed. Do not expose HTML
extraction on the strength of these tests alone.

Invocation: `launcher RUNTIME_DIR SCRATCH_DIR EXECUTABLE [ARG ...]`.
All paths/arguments must be operator-owned, not supplied by a document. Runtime
and scratch must be disjoint canonical directories; executable must be inside
runtime. The future runtime bundle must contain only Node, the worker, parse5,
entities, a module package.json and an empty openssl.cnf. No database or secrets.

Current restrictions:

- Fail closed without Linux x86-64, Landlock ABI >=3, seccomp, or close_range.
- Stdio must be pipes or verified unnamed AF_UNIX stream socketpairs (Node's
  child transport); named Unix/network sockets and regular files are rejected.
  All descriptors >=3 are closed. Empty environment except
  a fixed locale, no new privileges, dropped Linux capabilities, no core dumps.
- Runtime/system library directories are read/execute only. Only scratch permits
  regular-file/directory creation and mutation; no scratch execute permission.
- Network sockets, new processes, namespace manipulation, ptrace, cross-process
  memory, io_uring and other selected high-risk syscalls are denied. Threads are
  allowed; clone3 returns ENOSYS to use filterable clone flags.
- CPU 2 seconds soft/3 hard; address space 512 MiB; file size 8 MiB; 64 FDs.
  No claimed RSS/cgroup limit. RLIMIT_NPROC is deliberately absent because it is
  per-UID and bypassed for root, not a per-parser control. Threads share CPU/AS
  limits; there is no separate tested thread-count bound.
- ioctl is denied for descriptors >2. Node/libuv requires it for nonblocking
  stdio; descriptors 0–2 are checked as pipes/unnamed socketpairs before exec.

Verification on Ubuntu WSL: 15 tests pass in `test-support/sandbox-tests.py`,
including an actual Node 22.23.1/parse5 extraction with `--jitless`,
`--no-expose-wasm`, `--max-old-space-size=96`, `--max-semi-space-size=4`, and
`--openssl-config=RUNTIME_DIR/openssl.cnf`. The test checks exact synthetic text
and requires-review output. Other tests exercise CPU termination, memory refusal,
network/file/process denial, runtime read-only access, writable scratch, inherited
FD/environment stripping (with an unsandboxed positive control), thread startup,
symlink/hardlink/truncation escapes, scratch execution, file-size/FD-count bounds,
stdio socket types, overlapping directories and rejection of `/` as runtime.

Railway: 14 probe cases pass under UID 0 using the native launcher and portable
Node 22.23.1. These include file/network/process denial, links, scratch execution,
FD count, threads, memory, CPU and file-size signals, and a Node built-in probe
for protected reads, environment, process spawning and loopback connection denial.
The original host Node 22.11.0 uses a /nix/store loader and is correctly denied;
do not widen the library allowlist to accommodate that tree. Portable Node was
fetched with npm pack --ignore-scripts into the temporary probe directory and its
archive SHA-512 matched the locally tested bytes before extraction. The probe
cleans its runtime, package cache and synthetic files. Five additional full-worker
fixtures verify entity/active-content handling, table/footnote output, exact text
for 5,000 paragraphs, empty-content rejection and invalid UTF-8 rejection. Source
span bounds and requires-review markers are checked. No production DB access.

`parser-bundle.js` provides build-time `createParserBundle({destination,
nodeExecutable,launcherExecutable})`. It creates a new destination only, copies
the exact parse5 8.0.1/entities 8.1.0 distributions and licenses plus the worker,
explicit binary inputs, package.json and empty OpenSSL config. Every file receives
a size/SHA-256 entry in manifest.json. Binary inputs must be bounded single-link
regular files; links in dependency trees are rejected. Source inputs are trusted
build artifacts, not uploads. The manifest's required version/platform values
are requirements, not claims that packaging executed or authenticated the binaries.
Local Linux integration now tests a bundle generated by this function rather
than a hand-assembled runtime. Four separate packaging tests pass. The factory
does not download, compile, activate, verify kernel policy, or serve documents.
`verifyParserBundle({directory, expectedManifestSha256})` now checks a bounded
inventory and all file hashes against a manifest digest supplied separately by
the caller. It rejects modified/missing/extra files, linked files, traversal
entries and altered manifests. Twelve packaging/integrity tests pass; the full
backend suite passes 481 tests across 54 suites. Verification does not execute
or authenticate binaries, enforce platform compatibility, or prevent subsequent
mutation. The caller must obtain the digest from a trusted release and keep the
bundle and its parent path deployment-owned and immutable. Activation wiring
and deployment-owned sealing remain required; never derive the trusted digest
from the same potentially altered bundle immediately before checking it.

Run on Linux with GCC/libseccomp headers and Python 3:

```sh
EASY_PARSER_NODE_ARCHIVE=/path/to/node-linux-x64-22.23.1.tgz python3 server/test-support/sandbox-tests.py
```

Without the archive, the actual-parser test is skipped, not passed. The archive
is the exact npm `node-linux-x64@22.23.1` package; only package/bin/node is
extracted. Temporary tests hold synthetic data and are cleaned by the harness.
`EASY_PARSER_DIAGNOSTICS=1` changes only a temporary worker copy to expose errors
for synthetic test diagnosis; never enable document-content diagnostics in service.

Remaining gates: broader resource/escape adversarial coverage; larger legitimate
inputs beyond the synthetic sample; independent security review; activation
deployment configuration/sealing and build deployment; transactional extraction
manifests; API integration and human quality review gates.
Landlock does not mediate every metadata operation; this is defense in depth,
not a claim of complete kernel isolation or a general untrusted-code service.

Application integration: `extractHtml(bytes, {bundleDirectory, manifestSha256,
scratchParent, signal})` accepts only operator-owned configuration. It rejects
non-Linux/x64 hosts and missing/tampered bundles, creates a private scratch child,
uses the native launcher, bounds output at 8 MiB and elapsed runtime at 5 seconds,
and waits for child close before cleanup. New processes are denied by the native
policy; no separate generic process-tree guarantee is claimed. Stderr is drained
without retaining/logging document diagnostics. Result shape, review requirement
and text/source offset bounds are checked. Deployment-owned immutable paths are
still a prerequisite, not provided by this wrapper.

The Linux 15-test suite now includes eight application-wrapper scenarios: success,
missing configuration, cancellation, invalid UTF-8, altered worker, malformed
result, stalled worker, and excessive output. Each started invocation checks
scratch cleanup. The portable Jest fidelity/lifecycle tests use an explicitly
test-only worker harness; they do not bypass production platform restrictions.

Installed-runtime preflight: `node ops/check-parser-runtime.js /opt/easy-parser
/opt/easy-parser.sha256 /tmp/easy-html` runs as the non-root service account. It
requires zero inheritable/permitted/effective/ambient capabilities, root-owned
read-only files and directories (no special permission bits or hard links), safe
ancestors, an external trust record, and service-owned mode0700 scratch. It then
verifies the bundle and performs a real synthetic parse. It does not authenticate
the build or replace full sandbox adversarial/fidelity testing. Opt-in startup/API
wiring now uses this loader before accepting HTML work, but remains undeployed.
The same-UID low-level wrapper remains an internal primitive; production activation
must use the installed-runtime validation first.

To exercise the additional 12 ownership/preflight scenarios, run the actual-parser
test as root **in the disposable local Linux test environment**; root only owns
the temporary fixtures, and the application checks run in UID/GID1000 children:

```sh
EASY_PARSER_NODE_ARCHIVE=/path/to/node-linux-x64-22.23.1.tgz python3 server/test-support/sandbox-tests.py SandboxTests.test_actual_html_parser
```

The root-only subcases do not run in the ordinary non-root suite. Never run the
application itself as root to satisfy preflight: that is explicitly rejected.
